# 编译和烧录

本固件项目使用 **ESP-IDF 6.0.2** 完成开发与验证。编译、烧录和监视依赖 ESP-IDF 环境，
因此**每次新开终端都必须先加载对应平台的 ESP-IDF 环境**，并在正确的环境中执行命令。
请勿在 IDF 5.5.x 环境下编译或烧录本固件——旧版工具链会因 `esp_lcd_panel_dev_config_t`
等结构体字段顺序不同而报编译错误。

本文档按 **macOS / Linux / Windows** 三个平台分别说明。三者的 `build.py` 动作、板型
参数与烧录流程完全一致，差异仅在环境加载方式和串口端口名。

> 板型的目标芯片、组件依赖和 sdkconfig 默认值由 `main/boards/<board>/` 提供，
> **不要**执行 `idf.py set-target`。开发构建输出到 `build/<board>/debug`，不同芯片
> 使用互相隔离的配置和产物。

---

## 通用命令（三个平台相同）

以下命令在所有平台一致，唯一的区别是环境加载方式与串口端口名（见各平台章节）。

列出可用板型：

```bash
python scripts/build.py --list-boards
```

编译指定板型（当前已验证 `movecall-moji2-esp32c5`）：

```bash
python scripts/build.py movecall-moji2-esp32c5 build
```

只重新配置（依赖或 sdkconfig 变更后执行）：

```bash
python scripts/build.py movecall-moji2-esp32c5 reconfigure
```

打开菜单配置（显示样式、资源、调试选项等）：

```bash
python scripts/build.py movecall-moji2-esp32c5 menuconfig
```

清理增量缓存，执行一次完整干净构建：

```bash
python scripts/build.py movecall-moji2-esp32c5 fullclean
```

烧录固件（仅写设备）：

```bash
python scripts/build.py movecall-moji2-esp32c5 flash -p <端口>
```

烧录并跟随串口日志（监视）：

```bash
python scripts/build.py movecall-moji2-esp32c5 flash-monitor -p <端口>
```

> 注意：`build.py` 通过当前 shell 的 `PATH` 中的 `idf.py` 定位 ESP-IDF。
> 因此`source export.sh`（或 Windows 的 `export.bat`）之后才能运行上面的命令，
> 否则脚本会 fallback 到错误的 IDF 版本。

## macOS

### 环境加载

打开终端（建议新开终端避免残留旧环境变量），进入固件仓库根目录（monorepo 中即 `ESP32-C5.Firmware/`）并加载 IDF 6.0.2 环境：

```bash
source "$HOME/.espressif/v6.0.2/esp-idf/export.sh"
```

> 确认加载成功：
> ```bash
> echo $IDF_PATH            # 应输出 .../v6.0.2/esp-idf
> which idf.py              # 应指向 .../v6.0.2/esp-idf/tools/idf.py
> idf.py --version          # 应显示 ESP-IDF v6.0.2
> ```

### 串口端口

插入设备（USB）后，从 Finder 或命令行确认板子的串口端口，例如：

```bash
ls /dev/cu.usbmodem*
```

典型输出：`/dev/cu.usbmodem83101`

### 编译

```bash
python scripts/build.py movecall-moji2-esp32c5 build
```

### 烧录

```bash
python scripts/build.py movecall-moji2-esp32c5 flash -p /dev/cu.usbmodem83101
```

### 烧录并监视日志

```bash
python scripts/build.py movecall-moji2-esp32c5 flash-monitor -p /dev/cu.usbmodem83101
```

退出日志监视器按 `Ctrl+]`。

## Linux

### 环境加载

打开终端（建议新开终端避免残留旧环境变量），进入固件仓库根目录（monorepo 中即 `ESP32-C5.Firmware/`）并加载 IDF 6.0.2 环境：

```bash
source "$HOME/.espressif/v6.0.2/esp-idf/export.sh"
```

如果在某些发行版上 `$HOME/.espressif` 不可用，请将该路径改为实际安装 IDF 的位置。

> 确认加载成功：
> ```bash
> echo $IDF_PATH            # 应输出 .../v6.0.2/esp-idf
> which idf.py              # 应指向 .../v6.0.2/esp-idf/tools/idf.py
> idf.py --version          # 应显示 ESP-IDF v6.0.2
> ```

### 串口端口

设备通常枚举为 `/dev/ttyUSB0` 或 `/dev/ttyACM0`。查看可用端口：

```bash
ls /dev/ttyUSB* /dev/ttyACM* 2>/dev/null
```

烧录时通常需要给当前用户串口读写权限。两种方式任选其一：

- 将用户加入 `dialout` 组（推荐，需重新登录生效）：

  ```bash
  sudo usermod -aG dialout $USER
  ```

- 或每次临时授权：

  ```bash
  sudo chmod 666 /dev/ttyUSB0
  ```

### 编译

```bash
python3 scripts/build.py movecall-moji2-esp32c5 build
```

> Linux 发行版常用 `python3`；若 `python3` 不存在，可用 `python`。

### 烧录

```bash
python3 scripts/build.py movecall-moji2-esp32c5 flash -p /dev/ttyUSB0
```

（若设备为 `/dev/ttyACM0`，把端口换成 `/dev/ttyACM0`。）

### 烧录并监视日志

```bash
python3 scripts/build.py movecall-moji2-esp32c5 flash-monitor -p /dev/ttyUSB0
```

退出日志监视器按 `Ctrl+]`。

## Windows

建议使用 ESP-IDF 官方提供的 PowerShell 环境（安装 ESP-IDF 时一起安装的
"ESP-IDF 6.0.2 PowerShell" 快捷方式），它已配置好 IDF 与工具链。

### 环境加载

从 Windows 开始菜单启动 **"ESP-IDF 6.0.2 PowerShell"** 快捷方式，它会自动加载环境。
然后在其中进入固件仓库根目录（monorepo 中即 `ESP32-C5.Firmware/`）：

```powershell
cd <固件仓库根目录>
```

若使用普通 PowerShell / CMD，必须手动运行 IDF 的 `export.bat` 加载环境：

- 在项目根目录使用交互式终端（当前 shell 会影响环境变量）：

  ```bat
  call %USERPROFILE%\.espressif\v6.0.2\esp-idf\export.bat
  ```

> 确认加载成功：
> ```powershell
> $env:IDF_PATH            # 应输出 ...\v6.0.2\esp-idf
> idf.py --version         # 应显示 ESP-IDF v6.0.2
> ```

### 串口端口（USB 串口驱动）

Windows 下设备一般枚举为 `COM` 口。在 **设备管理器 → 端口 (COM 和 LPT)** 中查看
设备的 `COMx` 编号（例如 `COM4`）。通常需要安装 CH340 / CP210x 等 USB 转串口驱动。

> 若端口未出现，可能是串口驱动未安装或未使能，请先安装对应芯片的 USB 驱动。

### 编译

```powershell
python scripts/build.py movecall-moji2-esp32c5 build
```

### 烧录

```powershell
python scripts/build.py movecall-moji2-esp32c5 flash -p COM4
```

（把 `COM4` 换成设备管理器里实际的 COM 号。）

> 若端口被占用（返回 "Failed to connect"/超时），请关闭上一轮 monitor、
> 拔插 USB，或换一个 USB 口重试。

### 烧录并监视日志

```powershell
python scripts/build.py movecall-moji2-esp32c5 flash-monitor -p COM4
```

退出日志监视器按 `Ctrl+]`。

## 常见问题排查

| 现象 | 原因与解决办法 |
| --- | --- |
| 编译报 `designator order for field 'esp_lcd_panel_dev_config_t::reset_gpio_num'` | 用了 IDF 5.5.x 环境。**本固件只能用 IDF 6.0.2 编译/烧录**。重新加载 6.0.2 环境后再运行。 |
| `idf.py` 找不到或版本不对 | 未加载环境，或 shell 残留旧 IDF 变量。新开终端，重新 `source export.sh`（Windows：`export.bat`）后再执行。 |
| 烧录时报 "Failed to connect" / "No such file or directory"（端口） | 端口名写错、被其它程序占用、驱动未装或设备未枚举。mac 确认 `ls /dev/cu.usbmodem*`、Linux 确认 `/dev/ttyUSB*`、Windows 到设备管理器确认 `COMx`。 |
| Linux 下 `Could not open port /dev/ttyUSB0: Permission denied` | 当前用户无串口权限。加入 `dialout` 组或用 `sudo chmod 666 /dev/ttyUSB0`。 |
| `fullclean` 后报找不到 managed component 源文件 | `fullclean` 会清掉 `managed_components/` 缓存。重新执行一次 `build`，让 ESP-IDF 组件管理器自动重新下载缺失组件。 |

## 发布构建说明

发布构建使用 `python scripts/release.py <board>`，产出可直接烧录的完整合并镜像
（**非安全加固**版本：无 Secure Boot / Flash 加密 / 防降级，不写入不可逆 eFuse，可随时重刷）。
普通开发构建与发布构建均不会启用任何安全发布配置。
