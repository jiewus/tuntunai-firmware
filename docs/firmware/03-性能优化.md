当前已经完成静态表盘和原生时间字体，剩余性能热点主要有这些：

**1. SPI LCD 开启双缓冲**

当前配置仍是：

```cpp
.buffer_size = width_ * 20,
.double_buffer = false,
.buff_dma = 1,
```

位置在 `main/boards/movecall-moji2-esp32c5/display/lcd_screensaver.cc`。

这是目前最值得优先测试的项目。建议先改为：

```cpp
.buffer_size = width_ * 20,
.double_buffer = true,
```

预计额外占用约 14KB 内部 SRAM，但可以让 LVGL 绘制和 QSPI 发送重叠，改善界面切换和动画卡顿。

**2. 删除伪粗体重复绘制**

当前仍存在：

- `DrawBitmapBoldText`
- `EnableBitmapTextBold`
- `EnableLightweightBitmapTextBold`

这些逻辑会对同一段文字重复绘制 2 到 4 次，天气、日期、MCP 和绑定码都会受到影响。

建议后续改成：

- 固定数字使用原生字体；
- 动态中文使用完整主题字体；
- 不再通过重复绘制模拟粗体。

需要注意，不能再次强制使用基础 20px 字库，否则自定义城市和备忘录中的汉字可能缺失。

**3. 减少 `transform_scale` 使用**

当前屏保仍有多处运行时缩放：

- 天气；
- 日期；
- MCP；
- 绑定页；
- 对话字幕。

`transform_scale` 会增加布局计算和重绘成本，也是当前文字大小不一致的主要来源之一。

但这项不能简单全部删除，动态中文必须使用完整字体。最稳妥的方式是：

- 时间、数字、固定符号使用原生字体；
- 动态中文使用完整主题字体；
- 对动态中文只保留一套统一字号策略。

**4. 优化秒刻度更新**

当前每秒都会对秒刻度执行：

- 修改尺寸；
- 修改旋转中心；
- 修改旋转角度；
- 重新 `lv_obj_align`。

位置在 `main/boards/movecall-moji2-esp32c5/display/lcd_screensaver.cc`。

可以预计算 60 个秒刻度的位置和角度，更新时只调用位置更新，减少每秒布局计算。

**5. GIF 解码转移到 PSRAM**

当前 GIF 解码上下文仍主要使用 `lv_malloc`：

```text
gifdec.c:124
gifdec.c:130
```

可以将大于一定尺寸的 GIF 缓冲区优先放到 PSRAM，并启用 LZW 解码缓存。同时根据 GIF 实际帧延迟设置定时器，避免固定高频轮询。

这项主要改善：

- 表情动画卡顿；
- 内存不足；
- 音频播放期间的堆竞争。

**6. 合并后端临时任务**

天气、备忘录、MCP、通知目前会反复创建和销毁任务，任务栈大小为 8KB 到 16KB。

长期运行后可能产生：

- PSRAM 碎片；
- 任务创建失败；
- 多个任务竞争 HTTP 锁；
- 网络同步时界面短暂卡顿。

后续可以改成一个常驻后端 Worker，通过事件位或队列处理同步请求。

**7. 增加性能统计**

建议先增加以下指标，再继续调参：

- LVGL 单帧耗时；
- QSPI flush 耗时；
- LCD DMA 等待时间；
- LVGL 任务栈高水位；
- GIF 单帧解码耗时；
- 音频缓冲区最低水位；
- MQTT 音频序号丢失次数；
- SRAM/PSRAM 最小可用值。

推荐实施顺序：

1. SPI LCD 双缓冲；
2. 删除伪粗体重复绘制；
3. 优化秒刻度位置更新；
4. GIF PSRAM 解码；
5. 合并后端任务；
6. 根据统计结果再调整 LVGL 优先级。
