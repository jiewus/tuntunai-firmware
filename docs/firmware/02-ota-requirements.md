# Moji 2 OTA 功能需求

- 状态：需求基线
- 适用固件：`movecall-moji2-esp32c5`
- 默认版本检查地址：`https://api.tenclass.net/xiaozhi/ota/`

本文档定义设备使用小智官方 OTA 服务的行为，不改变设备的双 OTA 分区、启动回滚和
手动安全分区烧录能力。

## 1. 目标与非目标

### 1.1 目标

1. 设备开机联网后最多执行一次版本检查。
2. 版本检查访问小智官方 OTA 服务，获取固件版本和语音协议配置。
3. 检查失败是可恢复的外部依赖故障：记录日志后立即跳过，继续初始化语音协议，
   不弹窗、不播放失败提示、不重试、不阻塞开机。
4. 服务端返回新版本时，设备下载应用镜像到非运行 OTA 分区，校验成功后切换启动分区并重启。
5. 新镜像启动异常时由 bootloader 自动回滚到旧分区；正常启动完成后确认当前镜像有效。
6. 版本检查服务可以下发语音协议连接所需的 MQTT/WebSocket 配置，但这些配置的生命周期
   必须与固件版本检查逻辑解耦。

### 1.2 非目标

- 不实现资源分区（`assets`）的在线更新协议；资源更新继续使用现有 MCP 资源下载流程。
- OTA 不更新 bootloader、分区表、NVS 或资源分区。涉及这些内容时必须使用完整镜像或安全分区烧录流程。
- 不在设备端实现发布审批、灰度编排、设备分组或镜像托管，这些由后端 OTA 服务负责。

## 2. 设备端配置

### 2.1 默认地址

固件编译期默认值固定为：

```text
https://api.tenclass.net/xiaozhi/ota/
```

地址应通过项目 Kconfig/CMake 配置注入，代码中不得再出现其他硬编码的备用地址。

### 2.2 地址覆盖

生产固件暂不提供配网页面的“自定义 OTA 地址”输入项，避免用户配置一个设备不会使用的地址。
如后续确实需要测试环境切换，应增加受控的构建配置或仅限工程调试的 NVS 配置，并满足：

- 仅允许 `https`；
- 校验主机名和长度；
- 不把访问令牌、密码或完整请求头写入日志；
- 地址为空时回退到上述生产默认地址。

## 3. 启动时序

联网并完成基础网络初始化后，启动任务按以下顺序执行：

```text
启动硬件
  -> 连接 Wi-Fi/4G
  -> 尝试 OTA 版本检查（一次，失败即跳过）
  -> 应用待处理资源更新（如有）
  -> 从 NVS 读取 MQTT/WebSocket 配置
  -> 初始化语音协议
  -> 进入待命
```

版本检查不得成为语音协议初始化的前置硬依赖。无论检查成功、失败、超时或响应无更新，
都必须最终进入协议初始化路径。

## 4. 版本检查接口

### 4.1 请求

- 方法：`POST`
- URL：默认自有 OTA 地址
- 请求头：`Content-Type: application/json`、设备标识、固件版本和产品型号等已有系统信息头
- 超时：使用网络组件的有限连接/读取超时；不得在主任务中无限等待
- 请求体：沿用 `Board::GetSystemInfoJson()`，至少包含设备 UUID、MAC、板型、当前固件版本和硬件能力

### 4.2 响应

HTTP `200` 时响应体为 JSON。最小固件字段如下：

```json
{
  "firmware": {
    "version": "1.1.0",
    "url": "https://cdn.tuntun.life/moji2/1.1.0/xiaozhi.bin",
    "force": 0,
    "sha256": "可选，64 位十六进制摘要",
    "size": 1234567,
    "release_notes": "可选，仅用于服务端记录"
  }
}
```

字段规则：

- `firmware` 缺失表示无可用更新，不视为错误；
- `version` 和 `url` 必须同时为字符串，否则忽略更新；
- 版本号使用点分数字段（如 `1.2.0`），按数字逐段比较；
- `force=1` 可在版本号不高于当前版本时触发升级，但服务端必须谨慎使用；
- `sha256` 存在时设备必须在切换分区前校验，摘要不匹配则中止升级；
- `size` 存在时应校验下载长度，长度不一致则中止升级；
- 固件 URL 必须为 HTTPS，证书校验失败时中止升级。

响应可以包含语音协议配置（`mqtt`、`websocket`）或服务端时间，但这些字段与 `firmware`
独立处理。单独缺少 `firmware` 不得清除已有协议配置。

## 5. 失败与降级策略

以下情况均按“检查失败”处理：DNS/连接失败、TLS 失败、HTTP 非 `200`、响应 JSON 无法解析、
字段格式错误、读取超时和服务端返回错误码。

处理要求：

1. 输出一条 `WARN` 日志，包含阶段和错误分类；必要时记录 HTTP 状态码，禁止输出令牌和完整敏感请求体。
2. 不改变当前运行分区，不清除已有 MQTT/WebSocket 配置。
3. 不显示“检查新版本失败”提示，不播放告警音，不进入升级状态。
4. 不进行循环重试或指数退避；本次开机流程直接继续。
5. 下次设备正常重启时可再次检查。

示例日志：

```text
W (ota) 自有 OTA 版本检查跳过，原因=tls_error
W (ota) 自有 OTA 响应无可用固件，继续启动
```

下载或写入阶段失败时同样不得阻塞设备长期运行：释放 HTTP/OTA 句柄，保留旧分区，
记录失败原因并继续使用当前固件。只有镜像完整下载、校验通过且启动分区切换成功后才允许重启。

## 6. 升级与回滚

1. 使用 `esp_ota_get_next_update_partition()` 选择非运行分区。
2. 流式下载并写入，限制缓冲区在内部 RAM/项目既有内存策略范围内。
3. 校验镜像头、镜像长度（如提供）和 SHA-256（如提供）。
4. 调用 `esp_ota_set_boot_partition()` 成功后再重启。
5. 保留 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y`。
6. 启动初始化、网络和语音协议均完成后调用 `esp_ota_mark_app_valid_cancel_rollback()`，确认新镜像。
7. 若新镜像无法启动或在确认前崩溃，bootloader 自动回滚；回滚后下一次版本检查仍可重新获取目标版本。

OTA 应用镜像大小不得超过目标 OTA 分区容量。OTA 发布不得替代完整镜像烧录：
bootloader、分区表、NVS 结构或安全配置发生变化时，必须走 `docs/编译和烧录.md` 中的完整烧录流程。

## 7. 语音协议配置隔离

版本检查响应中的 `mqtt`、`websocket` 和服务端时间属于设备联网配置，不等同于固件升级结果：

- 配置字段有效时写入对应 NVS 命名空间；
- 字段缺失时保留现有值；
- OTA 请求失败时仍从 NVS 启动语音协议；
- 没有任何本地协议配置的新设备，需要通过独立的配网/绑定配置流程获得协议参数，不能依赖小智官方 OTA。

## 8. 服务端发布要求

OTA 服务至少需要：

- 根据设备型号和当前版本返回目标版本或空响应；
- 支持灰度、全量和强制升级策略；
- 镜像使用 HTTPS 静态下载地址，建议通过 CDN/对象存储承载；
- 返回与镜像匹配的 SHA-256 和大小；
- 保留发布、撤回、回滚记录；
- 对重复检查保持幂等，不因设备重试产生副作用。

推荐无更新响应为：

```json
{ "firmware": null }
```

或直接返回 `{}`；设备两者都必须视为“无更新”。

## 9. 可观测性与验收标准

设备日志至少覆盖：检查开始、检查跳过原因、发现版本、下载开始/完成、校验结果、分区切换、
回滚确认。日志不得包含访问令牌、密码或完整认证报文。

验收用例：

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| OTA-01 | OTA 服务 DNS/连接失败 | 无用户告警，设备继续进入待命和语音协议 |
| OTA-02 | OTA 服务返回 HTTP 500/非 JSON | 记录 WARN，不重试，不清除协议配置 |
| OTA-03 | 返回 `{}` 或 `firmware:null` | 设备保持当前版本并正常启动 |
| OTA-04 | 返回低版本固件 | 不下载、不重启 |
| OTA-05 | 返回新版本且摘要正确 | 写入备用分区、切换启动分区并重启 |
| OTA-06 | 下载长度或 SHA-256 不匹配 | 放弃切换，继续使用旧分区 |
| OTA-07 | 新镜像启动失败 | bootloader 回滚，设备可再次启动 |
| OTA-08 | OTA 检查失败但 NVS 有 MQTT/WebSocket | 仍使用 NVS 配置建立语音协议 |
| OTA-09 | 通过完整镜像烧录 | 可更新 bootloader/分区并按烧录文档重新配置设备 |
